# آنتی‌ویروس و «فایل ویروسی» — توضیح صادقانه و راه تأیید

اگر ویندوز یا آنتی‌ویروس شما هنگام دانلود یا اجرای بستهٔ ROMKA هشدار داد، این سند
دقیقاً می‌گوید چه اتفاقی افتاده، چطور خودتان مطمئن شوید فایل سالم است، و اگر باز هم
هشدار گرفتید چه کنید.

## ۱) بستهٔ ROMKA چه چیزی هست و چه چیزی نیست

| هست | نیست |
|---|---|
| ۱۳۰ فایل **متنی**: `.py`, `.html`, `.css`, `.js`, `.md`, `.ps1`, `.sh`, `.json` | هیچ فایل اجرایی کامپایل‌شده (`.exe`, `.dll`, `.msi`, `.scr`) |
| کد منبع خوانا و بدون مبهم‌سازی (no obfuscation / no packing) | نصب‌کننده‌ای که خودش را در ویندوز ثبت کند |
| کتابخانه‌ها از PyPI با `pip install -r requirements.txt` | دانلود فایل باینری از سرور ناشناس در زمان اجرا |
| هیچ اتصال شبکه‌ای در حالت پیش‌فرض (موتور محلی آفلاین) | ارسال داده به سرور ما (سروری وجود ندارد) |

یعنی بسته از نظر فنی «اسکریپت پایتون» است، نه برنامهٔ ویندوزی. اگر پیش‌نیاز
**Python 3.11+** نصب نباشد، بسته به‌تنهایی هیچ کاری نمی‌تواند بکند.

## ۲) چرا ممکن است هشدار بگیرید (سه علت رایج، هیچ‌کدام بدافزار نیست)

1. **Mark-of-the-Web / SmartScreen:** هر فایلی که از اینترنت دانلود شود، برچسب
   «از اینترنت آمده» می‌گیرد. ویندوز برای فایل‌های بدون امضای دیجیتال پیام
   *Windows protected your PC* یا *This file may be harmful* نشان می‌دهد. این پیام
   دربارهٔ «ناشر ناشناس» است، نه دربارهٔ کد.
2. **هیوریستیک روی اسکریپت‌های کمکی:** نسخهٔ «full» دو ابزار دارد که از نظر موتور
   آنتی‌ویروس شبیه رفتار مخرب است:
   - `scripts/doctor.py`: فهرست پروسه‌ها، خواندن پورت، و **بستن پروسهٔ مزاحم**؛
   - `scripts/verify_provider.py`: خواندن کلید API از متغیر محیطی و ارسال یک درخواست
     به آدرسی که *خودتان* تعیین می‌کنید.
   این‌ها برای رفع خطای پورت و تست GapGPT نوشته شده‌اند، ولی «پروسه بکش + پورت اسکن +
   کلید بخوان» الگوی کلاسیک PUP است. بنابراین یک نسخهٔ **Core** هم منتشر شده که این
   دو فایل و پوشهٔ `deploy/` را ندارد.
3. **پوشهٔ PowerShell:** `setup.ps1`/`run_dev.ps1` فقط `venv` می‌سازند، `pip install`
   می‌کنند و `uvicorn` را بالا می‌آورند؛ برخی محصولات امنیتی اجرای اسکریپت‌های
   PowerShell را به‌صورت پیش‌فرض محدود می‌کنند (این سیاست است، نه تشخیص ویروس).

## ۳) سه گام تأیید (به‌ترتیب)

### گام ۱ — هش فایل را مقایسه کنید
هش رسمی هر نسخه در فایل `...zip.sha256` کنار همان آرشیو در مخزن است.

```powershell
Get-FileHash .\romka-v0.2.4.zip -Algorithm SHA256
Get-Content .\romka-v0.2.4.zip.sha256     # باید همان عدد باشد
```
```bash
sha256sum romka-v0.2.4.zip
```

اگر عدد یکی بود، فایل بایتی همان چیزی است که ما ساختیم و تست کردیم.

### گام ۲ — خودتان از منبع بسازید (قوی‌ترین تأیید)
هیچ فایل آماده‌ای دانلود نکنید؛ کد را از Git بگیرید و همان را بسازید:

```bash
git clone https://github.com/Masoumiofficial/RomekaAi.git
cd RomekaAi
git checkout arena/4ebd498f-romekaai
python scripts/build_release.py --version 0.2.4 --sha256-file
# هش خروجی باید با هش منتشرشده یکی باشد (ساخت عمداً تکرارپذیر است)
```

این بهترین راه است: هم کد را می‌بینید، هم می‌توانید `git log` و دیف هر کامیت را بخوانید.

### گام ۳ — کد را بخوانید
فقط دو فایل «حساس» وجود دارد و هر دو کوتاه و خوانا هستند:
`scripts/doctor.py` و `scripts/verify_provider.py`. هیچ‌کدام داده‌ای به سرور شخص ثالث
نمی‌فرستند؛ آدرس شبکه فقط از پیکربندی خودتان می‌آید.

## ۴) اگر باز هم بلاک شد

**الف) نسخهٔ Core را دانلود کنید** (بدون `doctor.py`، بدون `verify_provider.py`، بدون
`deploy/`):

```
downloads/romka-v0.2.4-core.zip
```

در این نسخه، اگر پورت اشغال باشد، اسکریپت با پیام روشن متوقف می‌شود و کار تمام است —
هیچ ابزاری پروسه نمی‌بندد.

**ب) برچسب «از اینترنت» را بردارید** (بعد از تأیید هش در گام ۱):

```powershell
Unblock-File .\romka-v0.2.4.zip
Expand-Archive .\romka-v0.2.4.zip -DestinationPath C:\
```

**ج) در SmartScreen:** `More info` → `Run anyway`. هرگز «Don't run» را انتخاب نکنید
مگر این‌که هش را تأیید نکرده باشید.

**د) گزارش مثبت کاذب به سازندهٔ آنتی‌ویروس** (بهترین راه‌حل بلندمدت). برای Microsoft:
<https://www.microsoft.com/en-us/wdsi/filesubmission> — فایل را با گزینهٔ
*I believe this file is incorrectly detected* بفرستید. برای Kaspersky/Norton/ESET هم
فرم مشابه «False positive» دارند. با هش فایل و نام نسخه، بررسی سریع‌تر است.

**ه) اگر لازم شد، فقط پوشهٔ پروژه را استثنا کنید** (نه کل درایو، نه خاموش‌کردن
آنتی‌ویروس):

```powershell
# فقط پس از تأیید هش و خواندن کد؛ این کار محافظت را برای آن پوشه کم می‌کند
Add-MpPreference -ExclusionPath "C:\romka"
```

این کار را **پیش‌فرض پیشنهاد نمی‌کنیم**؛ راه‌حل درست، گزارش مثبت کاذب است.

## ۵) چرا فایل `.exe` نمی‌دهیم

یک فایل `.exe` بدون امضای دیجیتال (code signing certificate) در ویندوز **بیشتر** احتمال
هشدار دارد، و بدتر: کاربر نمی‌تواند کد را بخواند. توزیع به‌صورت سورس + `Python` یعنی
هر کسی می‌تواند ببیند برنامه چه می‌کند — که با اصل «شفافیت» این پروژه سازگارتر است.
اگر روزی `.exe` لازم شد، باید با گواهی امضای کد و انتشار SBOM همراه باشد.
