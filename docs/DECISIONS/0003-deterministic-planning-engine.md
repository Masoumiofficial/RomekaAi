# ADR-0003 — موتور برنامهسازی قطعی، نه متن LLM

- **تاریخ:** 2026-10-27 · **وضعیت:** Accepted (مهمترین تصمیم پروژه)

## مسئله
معیار موفقیت محصول «قابلاجرا بودن برنامه» است. مدل زبانی میتواند متن زیبایی بنویسد
ولی تضمین نمیکند دو کار همزمان نباشند، ظرفیت رعایت شود یا وابستگیها جابجا نشوند.

## تصمیم
`app/planning/engine.py`، یک solver قطعی روی اعداد «دقیقه از نیمهشب»:
1. ادغام بازههای مشغول (تعهدات ثابت + غذا + رفتآمد)؛
2. استخراج اسلاتهای آزاد؛
3. مرتبسازی توپولوژیک وابستگیها (Kahn + اولویت/موعد)؛
4. تخصیص با درنظرگیری ظرفیت تمرکز، انرژی، پنجره اوج، موعد و بافر؛
5. `validate_plan` مستقل قبل از نمایش.

مدل فقط **پیشنهاد** میدهد (عنوان/مدت/اولویت)؛ موتور **تصمیم** میگیرد.

## دلایل
- قابل تست، قابل تکرار، قابل توضیح؛
- هزینه صفر (بدون فراخوانی LLM برای هر برنامهریزی)؛
- شکستها بهصورت «deferred با دلیل» گزارش میشوند، نه پنهان در متن.

## ریسکها
- تخمین مدت وظایف همچنان ورودی انسانی/هیوریستیک است؛ بعداً باید از داده واقعی
  «مدت اجرا شده» یاد بگیرد.
- Solver حریصانهای است (first-fit)، نه بهینهساز جهانی؛ کافی و شفاف است.

## شواهد
۱۲ تست واحد + سناریو A/B؛ تست `alembic downgrade/upgrade` جداگانه.
