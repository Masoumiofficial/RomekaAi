# ADR-0001 — معماری Modular Monolith

- **تاریخ:** 2026-10-27 · **وضعیت:** Accepted

## زمینه
مخزن خالی بود؛ محیط توسعه ویندوز محلی و استقرار نهایی VPS تکسروره. نیاز به سامانهای
با هسته، حافظه، برنامهساز، متخصصها، پنل وب، API و کانالهای پیامرسان.

## گزینهها
1. میکروسرویسها + صف پیام + orchestrator کانتینری.
2. SPA جداگانه (React/Next) + بکند جداگانه.
3. **Modular monolith** (FastAPI) + UI سروررندرشده (Jinja2 + vanilla JS).

## تصمیم
گزینه ۳.

## دلایل
- تککاربره در فاز اول: پیچیدگی توزیعشدگی ارزشی ندارد.
- یک واحد استقرار = backup/لاگ/مهاجرت/HTTPS سادهتر و ارزانتر.
- بدون build step فرانتاند: اجرا روی ویندوز و VPS یکسان، بدون node_modules در production.
- RTL/فارسی و دسترسپذیری مستقیم در HTML قابلکنترل است.
- مرزهای ماژولار داخلی (`ai/`, `memory/`, `planning/`, `agents/`) بعداً امکان جداسازی میدهند.

## ریسکها / زمان بازبینی
اگر تیم یا بار به چند سرویس مستقل رسید (مثلاً پردازش پسزمینه سنگین یا چند مستأجر)،
بازبینی. شاخص: p95 پاسخ، تعداد workerها، نیاز به مقیاسبندی مستقل.

## جایگزین ردشده
Next.js/SPA جداگانه: دولایه استقرار، مشکل CORS/کوکی، و هزینه نگهداری بیشتر بدون
نیاز فعلی.
