## ۳) تصمیمات فنی (و دلیل)

1. **Modular Monolith** (FastAPI): تککاربره فعلی؛ یک واحد استقرار؛ بدون build step فرانت.
2. **SQLAlchemy + Alembic**: ORM-only (ضد SQLi)، مهاجرت نسخهدار با downgrade تستشده.
3. **موتور برنامهسازی قطعی** (مهمترین تصمیم): LLM فقط پیشنهاد میدهد؛ solver اعداد
   «دقیقه از نیمهشب» تصمیم میگیرد و `validate_plan` مستقل برنامه را تأیید میکند.
4. **لایه ProviderAdapter + موتور محلی آفلاین**: محصول بدون هیچ کلیدی کار میکند؛
   آداپتور `/chat/completions` نوشته شده ولی زنده تست نشده. Claude/Gemini بومی ادعا نشد.
5. **حداکثر ۲ متخصص پاسخگو** + منتقد مستقل: متخصص بیشتر ≠ کیفیت بیشتر؛ کاهش هزینه/خطا.
6. **ابزارها فقط در کد**: `definitions.json` نمیتواند دسترسیای را که کد نداده بگیرد.
7. **رجیستری مهارتها بدون اجرای کد خارجی**: وتوی مجوز/دسترسی، SBOM و مسیر بازگشت.
8. **SVG بومی بهجای Three.js/Chart.js**: بدون داده واقعی، نمودار/انیمیشن تزئینی است.

## ۷.۱) به‌روزرسانی ۲۰۲۶-۱۰-۲۸ — ورود دمو + مسیر GapGPT

**مشکلی که کاربر گزارش کرد:** «هر کاری کردم تو دمو وارد نشد». علت واقعی (دو مورد هم‌زمان):

2. حتی با ورود موفق، کوکی نشست `SameSite=Lax` داخل **iframe پیش‌نمایش** (سایت ثالث)
   ذخیره نمی‌شد و کاربر بلافاصله به `/auth` برمی‌گشت.

**تعمیرات (کد + تست + تست زنده):**

- حساب دموی واقعی و idempotent در `app/bootstrap.py` (ایمیل جداگانه `demo@romka.local`
  تا حساب شخصی کاربر دست‌نخورده بماند)، ۹ ردیف دادهٔ نمونه با پیشوند `[نمونه]`، و
  قاعدهٔ صریح: رمز حساب موجود **هرگز** بازنویسی نمی‌شود (تست دارد).
- `COOKIE_SAMESITE=auto`: روی HTTPS → `SameSite=None; Secure`، روی HTTP → `Lax`.
- انتقال نشست با توکن امضاشده در هدر (`Authorization: Bearer` یا `X-ROMKA-Session`)
  برای شرایطی که کوکی مسدود است؛ CSRF همچنان الزامی و تست‌شده.
- صفحه‌های HTML برای کاربر بدون کوکی، «پوستهٔ خالی» برمی‌گردانند (هیچ دادهٔ کاربری در
